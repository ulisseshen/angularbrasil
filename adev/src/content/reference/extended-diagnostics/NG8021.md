# Configuração Incorreta de Trigger do Defer {#defer-trigger-misconfiguration}

Este diagnóstico detecta triggers inacessíveis ou redundantes em blocos `@defer`.

```angular-ts
import {Component} from '@angular/core';

@Component({
  template: `
    @defer (on immediate; on timer(500ms)) {
      <large-component />
    }
  `,
})
class MyComponent {}
```

## O que há de errado com isso? {#whats-wrong-with-that}

O diagnóstico identifica vários padrões problemáticos na configuração de triggers do defer que levam a:

- **Código desnecessário** que nunca afeta o comportamento
- **Oportunidades de otimização perdidas** para melhor performance
- **Triggers de prefetch inacessíveis** que nunca serão executados

## Casos de aviso do diagnóstico {#diagnostic-warning-cases}

Este diagnóstico sinaliza os seguintes padrões problemáticos:

### `immediate` com triggers de prefetch {#immediate-with-prefetch-triggers}

```angular-ts {avoid, header: "prefetch nunca é executado"}
@Component({
  template: `
    @defer (on immediate; prefetch on idle) {
      <my-cmp />
    }
  `,
})
class MyComponent {}
```

```angular-ts {prefer, header: "remova o prefetch redundante"}
@Component({
  template: `
    @defer (on immediate) {
      <my-cmp />
    }
  `,
})
class MyComponent {}
```

### Timer de prefetch não é anterior ao timer principal {#prefetch-timer-not-earlier-than-main-timer}

```angular-ts {avoid, header: "prefetch é posterior ao principal"}
@Component({
  template: `
    @defer (on timer(100ms); prefetch on timer(3000ms)) {
      <my-cmp />
    }
  `,
})
class MyComponent {}
```

```angular-ts {avoid, header: "timing igual não oferece benefício"}
@Component({
  template: `
    @defer (on timer(500ms); prefetch on timer(500ms)) {
      <my-cmp />
    }
  `,
})
class MyComponent {}
```

```angular-ts {prefer, header: "prefetch dispara antes"}
@Component({
  template: `
    @defer (on timer(1000ms); prefetch on timer(500ms)) {
      <large-component />
    }
  `,
})
class MyComponent {}
```

### Prefetch sem triggers principais {#prefetch-without-main-triggers}

```angular-ts {avoid, header: "busca antecipada inesperada"}
@Component({
  template: `
    @defer (prefetch when someFlag()) {
      <heavy-comp />
    }
  `,
})
class MyComponent {
  someFlag = signal(false);
}
```

Esta configuração pode sugerir que o prefetch só será executado quando `someFlag` se tornar verdadeiro. No entanto, como o trigger principal ainda assume `on idle` por padrão, o conteúdo adiado pode ser buscado mais cedo durante o período ocioso do navegador, contornando efetivamente a condição pretendida.

```angular-ts {prefer, header: "defina explicitamente o trigger principal"}
@Component({
  template: `
    @defer (on interaction; prefetch when someFlag()) {
      <heavy-comp />
    }
  `,
})
class MyComponent {
  someFlag = signal(false);
}
```

### Triggers de prefetch e principais idênticos {#identical-prefetch-and-main-triggers}

```angular-ts {avoid, header: "trigger de viewport idêntico"}
@Component({
  template: `
    @defer (on viewport; prefetch on viewport) {
      <my-cmp />
    }
  `,
})
class MyComponent {}
```

```angular-ts {avoid, header: "alvo de interaction idêntico"}
@Component({
  template: `
    <button #loadBtn>Load</button>
    @defer (on interaction(loadBtn); prefetch on interaction(loadBtn)) {
      <large-component />
    }
  `,
})
class MyComponent {}
```

```angular-ts {prefer, header: "remova o prefetch redundante"}
@Component({
  template: `
    <button #loadBtn>Load</button>
    @defer (on interaction(loadBtn)) {
      <large-component />
    }
  `,
})
class MyComponent {}
```

```angular-ts {prefer, header: "use alvos diferentes para prefetch e principal"}
@Component({
  template: `
    <div #hoverArea>Hover to prefetch</div>
    <button #clickBtn>Click to load</button>
    @defer (on interaction(clickBtn); prefetch on hover(hoverArea)) {
      <large-component />
    }
  `,
})
class MyComponent {}
```

## Requisitos de configuração {#configuration-requirements}

[`strictTemplates`](tools/cli/template-typecheck#strict-mode) deve estar habilitado para que qualquer diagnóstico estendido seja emitido.
`deferTriggerMisconfiguration` não tem requisitos adicionais além de `strictTemplates`.

## E se eu não puder evitar isso? {#what-if-i-cant-avoid-this}

Este diagnóstico pode ser desabilitado editando o arquivo `tsconfig.json` do projeto:

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "deferTriggerMisconfiguration": "suppress"
      }
    }
  }
}
```

Veja [configuração de diagnósticos estendidos](extended-diagnostics#configuration) para mais informações.
