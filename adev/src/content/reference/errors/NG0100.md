# Expressão alterada após verificação {#expression-changed-after-checked}

<docs-video src="https://www.youtube.com/embed/O47uUnJjbJc"/>

O Angular lança um `ExpressionChangedAfterItHasBeenCheckedError` quando o valor de uma expressão é alterado depois que a detecção de mudanças foi concluída. O Angular só lança este erro no modo de desenvolvimento.

No modo de desenvolvimento, o Angular realiza uma verificação adicional após cada execução da detecção de mudanças, para garantir que os bindings não mudaram. Isso captura erros em que a view fica em um estado inconsistente. Isso pode ocorrer, por exemplo, se um método ou getter retorna um valor diferente a cada vez que é chamado, ou se um component filho altera valores em seu pai. Se qualquer um desses casos ocorrer, isso é um sinal de que a detecção de mudanças não está estabilizada. O Angular lança o erro para garantir que os dados sejam sempre refletidos corretamente na view, o que previne um comportamento errático da UI ou um possível loop infinito.

Este erro geralmente ocorre quando você adicionou expressões de template ou começou a implementar lifecycle hooks como `ngAfterViewInit` ou `ngOnChanges`. Também é comum ao lidar com status de carregamento e operações assíncronas, ou quando um component filho altera os bindings do seu pai.

## Depurando o erro {#debugging-the-error}

Os [source maps](https://developer.mozilla.org/docs/Tools/Debugger/How_to/Use_a_source_map) gerados pelo CLI são muito úteis durante a depuração. Navegue pela call stack até encontrar uma expressão de template em que o valor exibido no erro mudou.

Certifique-se de que não há alterações nos bindings do template depois que a detecção de mudanças é executada. Isso geralmente significa refatorar para usar o lifecycle hook correto do component para o seu caso de uso. Se o problema existir dentro de `ngAfterViewInit`, a solução recomendada é usar um constructor ou `ngOnInit` para definir valores iniciais, ou usar `ngAfterContentInit` para outros bindings de valores.

Se você faz binding para métodos na view, certifique-se de que a invocação não atualize nenhum dos outros bindings do template.
