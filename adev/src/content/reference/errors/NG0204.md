# Token de injeção inválido

Este erro ocorre quando o Angular não consegue resolver uma dependência de uma classe durante a injeção de dependência. Isso afeta com mais frequência classes que usam injeção pelo constructor, em que o Angular depende dos metadados do TypeScript para determinar os tipos dos parâmetros.

As causas mais comuns são:

1. Uma classe de service não tem o decorator `@Service()` ou `@Injectable`
2. Um `InjectionToken` não tem uma definição de provider adequada
3. Um parâmetro do constructor não pode ser resolvido

NOTE: A função `inject()` recebe um token explícito, então o cenário de "parâmetro não resolvível" não se aplica a ela diretamente. No entanto, se a classe injetada não tiver `@Service()` e tiver suas próprias dependências no constructor, o erro ainda pode ocorrer.

## Cenários comuns {#common-scenarios}

### Decorator `@Service()` ausente {#missing-service-decorator}

Quando uma classe tem dependências no constructor, mas não tem o decorator `@Service()`, o Angular não consegue resolver seus parâmetros:

```ts {header: 'Decorator @Service() ausente'}
export class UserClient {
  constructor(private http: HttpClient) {} // O Angular não consegue resolver isto
}
```

Adicione o decorator `@Service()` para corrigir isso:

```ts
@Service()
export class UserClient {
  constructor(private http: HttpClient) {}
}
```

### Parâmetros de constructor não resolvíveis {#unresolvable-constructor-parameters}

Este erro também aparece quando o Angular não consegue determinar o tipo de um parâmetro do constructor:

```ts
@Service()
export class DataStore {
  // O Angular não consegue resolver 'config' sem um provider
  constructor(private config: AppConfig) {}
}
```

Garanta que todos os parâmetros do constructor tenham providers configurados ou use `@Optional()` para dependências opcionais.

## Depurando o erro {#debugging-the-error}

A mensagem de erro inclui detalhes sobre qual token não pôde ser resolvido:

- `Can't resolve all parameters for X: (?, ?, ?)` — As marcas `?` indicam parâmetros não resolvíveis. Verifique se a classe tem `@Service` ou `@Injectable()` e se todas as dependências têm providers.
- `Token X is missing a ɵprov definition` — Um `InjectionToken` foi usado sem configurar um provider. Registre o token com um valor usando `{provide: TOKEN, useValue: ...}` ou adicione uma factory padrão à definição do token.

Trabalhe de trás para frente a partir do stack trace do erro para identificar onde ocorre a injeção problemática e, em seguida, verifique se:

1. A classe tem o decorator `@Service` ou `@Injectable()`
2. Todos os parâmetros do constructor têm providers registrados
3. Qualquer `InjectionToken` tem um provider configurado ou um valor padrão
