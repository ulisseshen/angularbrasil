# Dependência circular detectada

O Angular detectou uma dependência circular entre components, directives ou pipes. Este erro ocorre quando o component A importa o component B, e o component B (direta ou indiretamente) importa o component A, criando um ciclo.

Essa referência circular impede que o Angular inicialize corretamente os components, resultando em um erro como:

```text
NG0919: Cannot read @Component metadata. This can indicate a runtime circular dependency in your app that needs to be resolved.
```

Em versões mais antigas do Angular, você pode ver, em vez disso, um erro como:

```text
Cannot read properties of undefined (reading 'ɵcmp')
```

## Causas comuns {#common-causes}

### Imports mútuos entre components {#mutual-component-imports}

A causa mais comum é quando dois components importam um ao outro:

```angular-ts {header:"parent.ts"}
import {Component} from '@angular/core';
import {Child} from './child';

@Component({
  selector: 'app-parent',
  imports: [Child],
  template: '<app-child/>',
})
export class Parent {}
```

```angular-ts {header:"child.ts"}
import {Component} from '@angular/core';
import {Parent} from './parent';

@Component({
  selector: 'app-child',
  imports: [Parent],
  template: '<app-parent/>',
})
export class Child {}
```

### Referências circulares indiretas {#indirect-circular-references}

Dependências circulares também podem ocorrer por meio de arquivos intermediários:

```text
ComponentA -> ComponentB -> ComponentC -> ComponentA
```

## Resolvendo o erro {#resolving-the-error}

### Refatore a lógica compartilhada {#refactor-shared-logic}

Mova a funcionalidade compartilhada para um arquivo separado que não importe nenhum dos dois components:

```ts {header:"shared.service.ts"}
import {Service} from '@angular/core';

@Service()
export class SharedService {
  // Lógica compartilhada aqui
}
```

### Use imports somente de tipo {#use-type-only-imports}

Se você precisa apenas dos tipos do TypeScript, use `import type`:

```ts
import type {Parent} from './parent';
```

Imports somente de tipo são removidos em tempo de compilação e não contribuem para dependências circulares em tempo de execução.

### Reestruture a hierarquia de components {#restructure-component-hierarchy}

Considere se a dependência circular indica um problema de design. Muitas vezes, extrair a funcionalidade compartilhada para um terceiro component ou serviço é a solução mais limpa.

### Depurando dependências circulares complexas {#debugging-complex-circular-dependencies}

Em aplicações complexas, com muitos módulos, dependências circulares podem ser difíceis de identificar manualmente. Considere usar ferramentas como o [madge](https://www.npmjs.com/package/madge) para visualizar e detectar imports circulares:

```bash
# Instala o madge
npm install -g madge

# Verifica dependências circulares
madge --circular --extensions ts ./src

# Gera um grafo visual
madge --circular --extensions ts --image graph.svg ./src
```

Essas ferramentas podem ajudar a identificar cadeias de dependências circulares em todo o projeto e a gerar grafos visuais de dependências.
