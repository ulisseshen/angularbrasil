# Escrita de signal em um contexto não permitido

O Angular lança este erro quando um signal é escrito (com `set` ou `update`) enquanto um `computed` ou um template está sendo avaliado. Ambos devem apenas ler signals, então escrever em um deles nesse momento alteraria o estado no meio do cálculo.

A mensagem de erro informa qual dos dois casos ocorreu.

## Escrever em signals não é permitido em um `computed` {#writing-to-signals-is-not-allowed-in-a-computed}

Um `computed` deve derivar seu valor de outros signals, sem efeitos colaterais:

```typescript
count = signal(1);
total = signal(0);

doubled = computed(() => {
  this.total.set(this.count() * 2); // não permitido
  return this.count() * 2;
});
```

Se o valor depende apenas de outros signals, torne-o um `computed` em si, em vez de armazená-lo:

```typescript
count = signal(1);
total = computed(() => this.count() * 2);
```

Use `linkedSignal` se o valor também precisar ser gravável, ou um `effect` se a escrita for um efeito colateral da mudança.

O mesmo erro é lançado para escritas dentro do cálculo de um `linkedSignal`.

## Escrever em signals não é permitido enquanto o Angular renderiza o template {#writing-to-signals-is-not-allowed-while-angular-renders-the-template}

As expressões do template são executadas durante a renderização, então um método chamado a partir do template também não pode escrever em um signal:

```angular-ts
@Component({
  selector: 'app-example',
  template: '<p>{{ label() }}</p>',
})
export class Example {
  views = signal(0);

  label() {
    this.views.update((v) => v + 1); // não permitido
    return `Viewed ${this.views()} times`;
  }
}
```

Mova a escrita para o ponto onde a mudança realmente acontece. Escrever em signals é permitido em event listeners, lifecycle hooks, handlers de outputs e effects.

## Usando `untracked` {#using-untracked}

Uma escrita envolvida em `untracked` não lança erro. Use isso somente quando a escrita for intencional e não puder ser movida, e lembre-se de que os signals lidos dentro de `untracked` também não são rastreados.

## Depurando o erro {#debugging-the-error}

O stack trace aponta para a chamada a `set` ou `update`. A partir daí, procure o `computed`, o `linkedSignal` ou a expressão do template que a chamou.
