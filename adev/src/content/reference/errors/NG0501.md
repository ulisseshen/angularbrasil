# Siblings ausentes na hidratação

Este erro é semelhante ao [erro NG0500](errors/NG0500), mas significa que o processo de hidratação do Angular esperava mais nós irmãos (siblings) em um ponto específico do DOM e não os encontrou. Consulte a página do [erro NG0500](errors/NG0500) para ver as causas relacionadas à manipulação direta do DOM.

## Uma causa comum: conteúdo condicional que difere entre servidor e cliente {#a-common-cause-conditional-content-that-differs-between-server-and-client}

Além da manipulação direta do DOM, este erro muitas vezes acontece quando o conteúdo dentro de `@if` ou `@for` é renderizado de forma diferente no servidor e no momento em que o cliente faz a hidratação. Se o servidor renderizou uma condição como `true` (ou uma lista com mais itens), mas o cliente a vê como `false` (ou uma lista mais curta) quando a hidratação roda, o cliente acaba esperando menos nós irmãos do que o servidor realmente enviou. A hidratação então falha ao percorrer os siblings.

Uma forma comum de isso acontecer é quando um valor vem de um `input()`, mas, em vez de usar esse input diretamente (ou por meio de `computed()`), ele é copiado uma única vez para um `signal()` comum dentro de `ngOnInit()` ou do construtor:

```angular-ts
@Component({
  selector: 'app-example',
  template: `
    @if (visibleItems().length) {
      <ul>
        @for (item of visibleItems(); track item) {
          <li>{{ item }}</li>
        }
      </ul>
    }
  `,
})
export class Example {
  items = input<string[]>();

  // Isso só é executado uma vez. Se `items()` ainda não estiver pronto no
  // exato momento em que `ngOnInit` roda, este signal pode acabar com um
  // valor diferente no servidor do que no cliente. Isso significa que um
  // número diferente de nós DOM é renderizado em cada lado, o que causa
  // uma incompatibilidade de hidratação.
  visibleItems = signal<string[]>([]);

  ngOnInit() {
    this.visibleItems.set(this.items() ?? []);
  }
}
```

A correção é derivar o valor em vez de copiá-lo uma única vez. Assim, toda renderização, inclusive a primeira, sempre corresponde ao input:

```ts
export class Example {
  items = input<string[]>();

  visibleItems = computed(() => this.items() ?? []);
}
```

Se você também precisar permitir que os usuários sobrescrevam esse valor localmente, por exemplo, um botão "mostrar mais" que revela itens extras, use [`linkedSignal()`](guide/signals/linked-signal) em vez de um `signal()` comum definido por um lifecycle hook.

## Depurando o erro {#debugging-the-error}

Veja o [erro NG0500](errors/NG0500) para dicas sobre a depuração de causas relacionadas à manipulação direta do DOM.

Este erro sozinho não informa qual component o causou. A [extensão de navegador Angular DevTools](tools/devtools) pode ajudar: ela pode destacar o component exato onde a incompatibilidade de hidratação aconteceu. Depois de encontrá-lo, observe como ele calcula qualquer valor usado dentro de um `@if` ou `@for` em seu template. Verifique se esse valor vem diretamente de um `input()` (por meio de um binding no template ou de `computed()`), ou se ele é copiado para um signal dentro de um lifecycle hook, como mostrado acima.
