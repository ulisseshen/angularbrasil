# Valor inseguro usado em um contexto de URL de recurso {#unsafe-value-used-in-a-resource-url-context}

O Angular lança este erro, com a mensagem `unsafe value used in a resource URL context`, quando um template ou um host binding define um atributo que carrega um recurso externo, como `<iframe src>` ou `<link href>`, com um valor que não foi explicitamente marcado como confiável.

URLs de recursos são tratadas de forma diferente das URLs comuns. O Angular consegue sanitizar uma URL simples, mas não consegue tornar segura uma URL de recurso qualquer, porque esses atributos fazem o browser buscar e executar conteúdo externo. Por isso, o Angular rejeita valores não confiáveis em vez de tentar sanitizá-los.

Os atributos que disparam esta verificação são:

| Elemento   | Atributo(s)        |
| ---------- | ------------------ |
| `<base>`   | `href`             |
| `<embed>`  | `src`              |
| `<frame>`  | `src`              |
| `<iframe>` | `src`              |
| `<link>`   | `href`             |
| `<object>` | `codebase`, `data` |

## Depurando o erro {#debugging-the-error}

O erro é lançado quando qualquer string simples é vinculada a um dos atributos acima, mesmo para uma URL que parece estática:

```angular-ts
@Component({
  selector: 'app-root',
  template: `<iframe [src]="url"></iframe>`,
})
export class App {
  url = 'https://example.com/embed';
}
```

Passar o valor por `DomSanitizer.sanitize()` com `SecurityContext.URL` também não resolve. `sanitize()` retorna uma string simples, e uma string simples nunca é aceita em um contexto de URL de recurso:

```angular-ts
@Component({
  selector: 'app-root',
  template: `<iframe [src]="sanitized"></iframe>`,
})
export class App {
  private readonly sanitizer = inject(DomSanitizer);
  sanitized = this.sanitizer.sanitize(SecurityContext.URL, 'https://example.com/embed'); // continua lançando NG0904
}
```

Chamar `sanitize()` com `SecurityContext.RESOURCE_URL` também lança erro, mas com o [NG05201](errors/NG05201), porque `sanitize()` não consegue tornar segura, em um contexto de URL de recurso, uma string arbitrária.

Se a URL vier de uma fonte confiável e controlada, marque-a como segura usando `DomSanitizer.bypassSecurityTrustResourceUrl`:

```angular-ts
import {DomSanitizer, SafeResourceUrl} from '@angular/platform-browser';
import {Component, inject} from '@angular/core';

@Component({
  selector: 'app-root',
  template: `<iframe [src]="safeUrl"></iframe>`,
})
export class App {
  safeUrl: SafeResourceUrl = inject(DomSanitizer).bypassSecurityTrustResourceUrl(
    'https://example.com/embed',
  );
}
```

CRITICAL: `bypassSecurityTrustResourceUrl` é uma saída de emergência, não um sanitizador. Nunca passe URLs fornecidas pelo usuário por ele, pois isso permitiria que um atacante carregasse conteúdo arbitrário, incluindo scripts maliciosos. Use-o somente quando o valor estiver totalmente sob o seu controle.

Para mais informações, veja o [guia de segurança](best-practices/security#trusting-safe-values).
