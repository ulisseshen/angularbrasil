# Ciclo de import detectado {#import-cycle-detected}

Um component, directive ou pipe referenciado por este component exigiria que o compilador adicionasse um import que levaria a um ciclo de imports.
Por exemplo, considere um cenário em que um `Parent` referencia um `Child` em seu template:

```angular-ts {header:"parent.ts"}
import {Component} from '@angular/core';
import {Child} from './child';

@Component({
  selector: 'app-parent',
  imports: [Child],
  template: '<app-child/>',
})
export class Parent {}
```

```angular-ts {header:"child.ts"}
import {Component, inject} from '@angular/core';
import {Parent} from './parent';

@Component({
  selector: 'app-child',
  template: 'The child!',
})
export class Child {
  private parent = inject(Parent);
}
```

Já existe um import de `child.ts` para `parent.ts`, já que o `Child` referencia o `Parent` em seu construtor.
HELPFUL: O template do component pai contém `<child></child>`.
O código gerado para este template deve, portanto, conter uma referência à classe `Child`.
Para fazer essa referência, o compilador teria que adicionar um import de `parent.ts` para `child.ts`, o que causaria um ciclo de imports:

```text

parent.ts -> child.ts -> parent.ts

```

## Remote scoping {#remote-scoping}

Se você estiver usando NgModules, para evitar adicionar imports que criam ciclos, código adicional é incluído na classe `NgModule` em que o component que conecta as dependências é declarado.

Isso é conhecido como "remote scoping".

## Bibliotecas {#libraries}

Infelizmente, o código de "remote scoping" tem efeitos colaterais —o que impede o tree shaking— e não pode ser usado em bibliotecas.
Por isso, ao construir bibliotecas usando a configuração `"compilationMode": "partial"`, qualquer component que exigir um import cíclico fará com que o erro de compilador `NG3003` seja lançado.

## Depurando o erro {#debugging-the-error}

O ciclo que seria gerado é mostrado como parte da mensagem de erro.
Por exemplo:

```text {hideCopy}

The component Child is used in the template but importing it would create a cycle:
/parent.ts -> /child.ts -> /parent.ts

```

Use isso para identificar como o component, pipe ou directive referenciado tem uma dependência de volta para o component que está sendo compilado.
Aqui estão algumas ideias para corrigir o problema:

- Tente reorganizar suas dependências para evitar o ciclo.
  Por exemplo, use uma interface intermediária armazenada em um arquivo independente que possa ser importada pelos dois arquivos dependentes sem causar um ciclo de imports.
- Mova as classes que se referenciam mutuamente para o mesmo arquivo, para evitar quaisquer imports entre elas.
- Converta as declarações de import em imports somente de tipo \(usando a sintaxe `import type`\) se as declarações importadas forem usadas apenas como tipos, pois imports somente de tipo não contribuem para ciclos.
