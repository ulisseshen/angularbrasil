# URL de recurso insegura passada ao DomSanitizer {#unsafe-resource-url-passed-to-domsanitizer}

O Angular lança este erro, com a mensagem `unsafe value used in a resource URL context`, quando `DomSanitizer.sanitize()` é chamado com `SecurityContext.RESOURCE_URL` e com um valor que não foi explicitamente marcado como confiável.

URLs de recursos são tratadas de forma diferente das URLs comuns. O Angular consegue sanitizar uma URL simples, mas não consegue tornar segura uma URL de recurso qualquer, porque atributos de recurso, como `<iframe src>` ou `<link href>`, fazem o browser buscar e executar conteúdo externo. Por isso, `sanitize()` rejeita valores não confiáveis em vez de tentar sanitizá-los.

Vincular um valor não confiável a um desses atributos em um template ou em um host binding lança o [NG0904](errors/NG0904) em vez deste erro.

## Depurando o erro {#debugging-the-error}

Procure por uma chamada a `sanitize()` que use `SecurityContext.RESOURCE_URL`. O erro é lançado para qualquer string simples, mesmo para uma URL que parece estática:

```angular-ts
@Component({
  selector: 'app-root',
  template: `<iframe [src]="url"></iframe>`,
})
export class App {
  private readonly sanitizer = inject(DomSanitizer);
  url = this.sanitizer.sanitize(SecurityContext.RESOURCE_URL, 'https://example.com/embed'); // lança NG05201
}
```

Se a URL vier de uma fonte confiável e controlada, marque-a como segura usando `DomSanitizer.bypassSecurityTrustResourceUrl` e faça o binding do resultado diretamente:

```angular-ts
import {DomSanitizer, SafeResourceUrl} from '@angular/platform-browser';
import {Component, inject} from '@angular/core';

@Component({
  selector: 'app-root',
  template: `<iframe [src]="safeUrl"></iframe>`,
})
export class App {
  safeUrl: SafeResourceUrl = inject(DomSanitizer).bypassSecurityTrustResourceUrl(
    'https://example.com/embed',
  );
}
```

CRITICAL: `bypassSecurityTrustResourceUrl` é uma saída de emergência, não um sanitizador. Nunca passe URLs fornecidas pelo usuário por ele, pois isso permitiria que um atacante carregasse conteúdo arbitrário, incluindo scripts maliciosos. Use-o somente quando o valor estiver totalmente sob o seu controle.

Para mais informações, veja o [guia de segurança](best-practices/security#trusting-safe-values).
